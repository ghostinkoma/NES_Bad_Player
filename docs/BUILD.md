## 2. cc65 の基本（初めての方向け）

cc65 は 6502 系 CPU 用の開発ツール一式です。今回は C コンパイラ（cc65.exe）は使わず、
**アセンブラ ca65** と **リンカ ld65** だけを使います。

```
 main.s ──(ca65: アセンブル)──> main.o ──(ld65: リンク + unrom.cfg)──> phase1.nes
 *.inc は main.s から .include で読み込まれる
```

| ツール | 役割 |
|---|---|
| `ca65.exe` | アセンブラ。`.s`（ソース）を `.o`（オブジェクト）に変換する。まだアドレスは決まっていない |
| `ld65.exe` | リンカ。`.o` を `.cfg` の指示どおりのアドレスに配置し、`.nes` を出力する |
| `cl65.exe` | 上の2つをまとめて呼ぶ便利コマンド（今回は使わなくてよい） |
| `da65.exe` | 逆アセンブラ。`.nes` の中身を確認したいときに使う |

### 2.1 .nes ファイルの中身
```
[iNES ヘッダ 16バイト][PRG-ROM 32KB]
```
- **iNES ヘッダ**: エミュレータやマジコンに「マッパー番号・ROM サイズ・ミラーリング」を伝える。
  `main.s` の `.segment "HEADER"` に書いてある。
- **PRG-ROM**: 6502 のプログラム。CPU アドレス `$8000-$FFFF` に見える。
- **CHR**: 今回は ROM を持たず **CHR-RAM 8KB** を使う（ヘッダの CHR サイズ = 0）。
  絵のデータは実行中に外部から書き込む。これは後で RP2354 が CHR を供給する構成の練習も兼ねている。
- マッパーは **UNROM（mapper 2）**。多くのマジコンが対応しているため、第3フェーズでもそのまま使える。

### 2.2 リンカ設定 (.cfg) の読み方
`nes/cfg/unrom.cfg`:
- `MEMORY` … 領域の一覧。`file = %O` が付いた領域だけが、書いた順に出力ファイルへ入る。
- `SEGMENTS` … ソース中の `.segment "CODE"` などを、どの領域に置くか。
- `VECTORS` は `$FFFA` 固定。ここに NMI / RESET / IRQ の飛び先アドレスを書く（6502 の決まり）。

### 2.3 ca65 の文法メモ（main.s を読むためのもの）

| 書き方 | 意味 |
|---|---|
| `lda #$10` | `#` 付き = 即値（数値そのもの）を A レジスタに入れる |
| `lda $10` / `lda MB_FLAG` | `#` なし = そのアドレスの中身を読む |
| `$FF` / `%1010` / `255` | 16進 / 2進 / 10進 |
| `#<ADDR` / `#>ADDR` | 16bit 値の下位バイト / 上位バイト |
| `NAME = $2000` | 定数の定義（メモリは消費しない） |
| `label:` | ラベル（アドレスに名前を付ける） |
| `@loop:` | ローカルラベル（直前の通常ラベルまたは `.proc` の中だけで有効） |
| `:` と `bcc :+` | 名前なしラベルと、その「次の名前なしラベル」への分岐 |
| `.proc name` 〜 `.endproc` | 関数のまとまり（中のラベルが外と衝突しない） |
| `.segment "CODE"` | 以降のコード/データをどのセグメントに置くか |
| `.byte` / `.word` / `.res n` | 1バイトデータ / 2バイトデータ / n バイト確保 |
| `.include "x.inc"` | ファイルの取り込み |
| `.repeat 8, I` 〜 `.endrepeat` | 同じコードを 8 回展開（I = 0〜7） |

詳しいリファレンス: `D:\hobby\nes\html\ca65.html`、`ld65.html`

## 3. ビルド手順

### 3.1 build.ps1 を使う（推奨）
PowerShell で `project` フォルダに移動して実行します。

```powershell
cd D:\hobby\nes\project
```
```powershell
.\build.ps1
```

成功すると `ビルド成功: build\phase1.nes (32784 バイト)` と表示されます。

> **PowerShell の注意点**
> - 今いるフォルダのスクリプトは、名前だけ（`build.ps1`）では実行されません。必ず `.\` を付けます（安全のための PowerShell の仕様）。
> - 「このシステムではスクリプトの実行が無効になっているため…」と出た場合は、実行ポリシーが原因です。
>   この PC の現在のユーザー設定は `RemoteSigned`（自分で作ったスクリプトは実行可）なので、通常は出ません。
>   出た場合は、そのときだけ許可して実行できます:
>   `powershell -ExecutionPolicy Bypass -File .\build.ps1`
> - `.ps1` を編集するときは **UTF-8（BOM 付き）** で保存してください。BOM が無いと Windows PowerShell 5.1 で日本語が文字化けし、エラーになることがあります。

### 3.2 手動でコマンドを打つ場合
`project` フォルダで次の2つを順に実行します（build.ps1 がやっていることと同じ）。

```powershell
..\bin\ca65.exe -g -I nes\src -o build\main.o nes\src\main.s
```
```powershell
..\bin\ld65.exe -C nes\cfg\unrom.cfg -o build\phase1.nes --dbgfile build\phase1.dbg -m build\phase1.map build\main.o
```

| オプション | 意味 |
|---|---|
| `-g` | デバッグ情報を付ける（Mesen2 でソースを見ながらデバッグできる） |
| `-I nes\src` | `.include` するファイルを探すフォルダ |
| `-o` | 出力ファイル名 |
| `-C` | リンカ設定ファイル |
| `--dbgfile` | デバッグ情報ファイル（Mesen2 が自動で読み込む） |
| `-m` | マップファイル（各セグメントがどのアドレスに置かれたかの一覧） |

### 3.3 出力ファイル

| ファイル | 内容 |
|---|---|
| `build\phase1.nes` | ROM 本体（32,784 バイト） |
| `build\phase1.dbg` | デバッグ情報。`.nes` と同じフォルダ・同じ名前なら Mesen2 が自動で読み込む |
| `build\phase1.map` | メモリ配置一覧。コードが何バイトあるかなどの確認用 |
| `build\main.o` | 中間ファイル（消してよい） |

## 4. 実行手順（エミュレータでお絵描き）

### 4.1 準備（初回のみ）
1. **Mesen2** をインストールする（https://www.mesen.ca/ ）。
   ※ FCEUX でも bridge.lua は動く作りにしてあります。
   ※ **LuaNES**（LÖVE 上で動く Lua 製エミュレータ）で動かす手順は [LUANES.md](LUANES.md) を参照。`.\run_luanes.ps1` で起動できます。
2. **Python 3**（3.10 以上）が入っていることを確認する。追加ライブラリは不要（標準の Tkinter のみ使用）。

### 4.2 起動の順番
1. **ROM をビルド**: `.\build.ps1`
2. **お絵描きツールを起動**: `.\run_paint.ps1`（または `python tools\paint\nes_paint.py`。引数も渡せます 例: `.\run_paint.ps1 --zoom 3`）
   - 起動すると `build\bridge\state.bin` が作られます。
3. **Mesen2 で ROM を開く**: `build\phase1.nes` をドラッグ＆ドロップ。
   - 白い画面の中央に、細かい点模様に囲まれた白い四角（キャンバス）が出ます。
4. **Lua ブリッジを読み込む**: Mesen2 のメニュー「デバッグ → スクリプトウィンドウ」を開き、
   `tools\emu_bridge\bridge.lua` を開いて実行する。
   - **ファイル入出力の許可が必要です。** スクリプトウィンドウ（または設定画面のスクリプト関連の項目）にある
     「I/O / OS 関数へのアクセスを許可」系のチェックを ON にしてから実行してください
     （項目名は Mesen2 のバージョンによって多少異なります）。
   - ログに `bridge: ROM に接続しました` と出れば接続成功です。
5. GUI で描くと、1〜数フレーム（約 0.05 秒）でエミュレータ画面に反映されます。
   エミュレータでパッドのボタン（既定ではキーボード）を押すと、GUI 右下に表示されます。

> **ブリッジフォルダを変える場合**: `bridge.lua` 冒頭の `BRIDGE_DIR` と、
> GUI の「ファイル → ブリッジフォルダ変更」（または `--bridge` 引数）を同じ場所にしてください。

### 4.3 お絵描きツールの操作

| 操作 | 内容 |
|---|---|
| 左ドラッグ | 選択中のツールで描く |
| 右クリック | スポイト（その点のパレットと色を拾う） |
| パレット欄の色枠をクリック | 描画色を選ぶ（P0〜P3 × 色0〜3。色0 は全パレット共通の背景色） |
| 64色表をクリック | 選択中の色枠の色を変更（$0D は赤斜線 = 使用非推奨） |
| `P` `E` `I` `A` | ペン / 消しゴム / スポイト / パレット割当 |
| `0`〜`3` | 選択中パレットの色番号を選ぶ |
| `G` | グリッド表示の切り替え |
| `Ctrl+Z` / `Ctrl+S` / `Ctrl+O` | 元に戻す / 保存 / 開く |
| ファイル → ファミコン用データ書き出し | `xxx_chr.bin`（4096B）/ `xxx_attr.bin`（64B）/ `xxx_pal.bin`（32B）を出力。第3フェーズで ROM に埋め込む用 |

**ファミコンの制約**: オレンジ色の線で区切られた 16×16 ドットのブロックごとに、
使えるパレットは1つ（3色＋背景色）だけです。ペンで別パレットの色を置くと、そのブロック全体の配色が変わります。

キャンバスは **128×120 ドット**（16×15 タイル = 240 タイル）です。
ファミコンの BG が一度に使えるタイルは 256 枚なので、すべてのタイルを別々の絵にできるのはこの大きさまでです。
全画面（256×240）のビットマップ表示は、RP2354 がパターンを動的に供給する第4フェーズ以降で実現します。

## 5. 仕組み

```
nes_paint.py ──state.bin──> bridge.lua ──CPU RAM $0300〜──> 6502 (NMI) ──$2006/$2007──> PPU
     ^                         │
     └──────── pad.txt ────────┘ <── 6502 が毎フレーム $0320 にパッド状態を書く
```

- ファミコン側（6502）は「メールボックスに置かれたデータを VBlank 中に PPU へコピーする」ことと
  「パッド状態を書き出す」ことしかしません。**第4フェーズ以降は bridge.lua の役割を RP2354 が担当**します。
- 1 フレームで送れるのは最大 128 バイト（実測 約 1,330 サイクル。VBlank は約 2,270 サイクル）。
  画面全体（4,192 バイト）は約 33 フレーム（0.6 秒）で送れます。1 ドットの変更なら 1 フレームで済みます。

### 5.1 メールボックス仕様（CPU RAM）

| アドレス | 書く側 | 内容 |
|---|---|---|
| `$0300` | 外部 → 6502 | フラグ。外部がデータを置いてから最後に `1` を書く。6502 が処理後 `0` に戻す |
| `$0301` / `$0302` | 外部 | 転送先 PPU アドレス 上位 / 下位 |
| `$0303` | 外部 | 転送バイト数 ÷ 8（1〜16）。範囲外のパケットは捨てられる |
| `$0380-$03FF` | 外部 | 転送データ（最大 128 バイト） |
| `$0320` | 6502 | パッド1（bit7〜0 = A B SELECT START 上 下 左 右） |
| `$0321` | 6502 | フレームカウンタ |
| `$0323` | 6502 | 初期化完了で `$A5` |
| `$0324` | 外部 | 接続時に `$5A`。リセットで 0 に戻るので、外部はこれを見て全データを送り直す |

### 5.2 state.bin 仕様（GUI → ブリッジ）

| オフセット | サイズ | 内容 |
|---|---|---|
| 0 | 8 | `NESPAINT` |
| 8 | 4 | 連番 seq（リトルエンディアン） |
| 12 | 2+2 | バージョン = 1、予約 |
| 16 | 4096 | CHR（PPU `$0000-$0FFF`） |
| 4112 | 64 | 属性テーブル（PPU `$23C0`） |
| 4176 | 32 | パレット（PPU `$3F00`） |
| 4208 | 4 | seq（先頭と同じ値。違えば書き込み途中と判断して読み飛ばす） |

## 6. トラブルシューティング

| 症状 | 対処 |
|---|---|
| `build.ps1` で `ca65.exe が見つかりません` | cc65 の展開場所が違う。`build.ps1` の `$Cc65Bin` を修正 |
| `用語 'build.ps1' は…認識されません` | 先頭に `.\` を付けて `.\build.ps1` と入力する |
| `スクリプトの実行が無効になっている` | `powershell -ExecutionPolicy Bypass -File .\build.ps1` で実行する |
| `Error: ... Unresolved external` などリンクエラー | ラベル名の打ち間違い。エラーに出た名前を `main.s` で確認 |
| bridge.lua で `io ライブラリが使えません` | Mesen2 のスクリプト設定で I/O アクセスを許可する |
| bridge.lua で `memType が見つかりません` | エラーに表示された候補名を `bridge.lua` の候補リストに追加する |
| `state.bin がまだありません` | GUI が起動していない、またはブリッジフォルダが一致していない |
| GUI で描いても反映されない | 「エミュレータへ自動送信」が ON か確認。Mesen2 が一時停止していないか確認 |
| 色がテレビ/実機と違う | 「ファイル → 表示用パレット(.pal)読み込み」で実機寄りのパレットに差し替える（方針: 近似値で妥協） |
