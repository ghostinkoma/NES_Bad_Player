# フェーズ2.x: ROM に入れた動画をフルサイズで再生する（Mesen 用）

ROM に入れておいた動画を、ファミコンの画面いっぱい（256×240）で再生します。
電源を入れるとまずオープニング（Bad Player のロゴ → 最後のコマで 20 フレーム停止 → 「(C) Ghostinkoma」を出して 20 フレーム
→ 黒い画面に英語の免責文（1 行ずつ出したあと 2 秒）、全部で約 8.6 秒）が流れ、終わるとメニュー
（PuniNeko のループ + スプライトの文字）に移ります。メニューで 4 本の動画から選んで再生します。
オープニングは START で飛ばせます。メニューの「0 OPENING」からもう一度見ることもできます。

| 段階 | 内容 | 状況 |
|---|---|---|
| 1 | Origen（2値）だけで仕組みと容量を実測 | ✅（2026-11-23） |
| 2 | メニュー、再生モード、FPS 表示、コマ戻し、Opening | ✅ 作成済み・Mesen で自動確認済み（2026-11-23） |
| 3 | 音声（DPCM）と映像の同期 | ✅ 作成済み・Mesen で自動確認済み（2026-11-23） |
| 4 | Tetsuy Komuro Remix（4値グレー）、2026AI（カラー） | ✅ 作成済み・Mesen で自動確認済み（2026-11-23） |
| 5 | オープニングを Bad Player のロゴ（固定4色）に差し替え、起動時に流してからメニューへ | ✅ 作成済み・Mesen で自動確認済み（2026-11-23） |

## 1. 使い方

PowerShell で `D:\hobby\nes\project` に移動して実行します。

1. ROM を作る（初回は 15〜20 分。2 回目からは変換結果を使い回すので 1 分ほど）

```powershell
.\build_video.ps1
```

2. Mesen で再生する

```powershell
.\run_mesen.ps1
```

### 操作
| 画面 | ボタン | 動き |
|---|---|---|
| メニュー | ↑ ↓ | 動画を選ぶ（黄色が選択中） |
| | A | 再生 |
| | SELECT | 再生モードを切り替え: REPEAT → STOP → SEQ |
| 再生中 | B | 一時停止 / 再開 |
| | →（一時停止中） | 1 コマ送り |
| | ←（一時停止中） | 1 コマ戻し（一瞬画面が消えます。グレー・カラーは最大 1 秒ほど） |
| | SELECT | FPS 表示の ON / OFF（左上に「FPS 30」など。その 1 秒で表示したコマ数） |
| | START | メニューに戻る |

### 再生モード（メニューの MODE）
| モード | 最後まで再生したら |
|---|---|
| REPEAT | 同じ動画を最初から繰り返す |
| STOP | 最後のコマで止まる（← で戻れる。B でもう一度最初から） |
| SEQ | 次の動画へ（0 → 1 → 2 → 3）。最後の動画の後はメニューへ |

### 動画の一覧（`tools/video/titles.json`）
| 番号 | メニューの表示 | 素材 | 表示 | コマ数 | 映像の量の上限 |
|---|---|---|---|---|---|
| 0 | OPENING | `resouce/openig/bmp`（Bad Player のロゴ、音なし。抜けている intro150 は 149 を繰り返す） | 固定4色（黒・白・赤・緑） | 30fps | 10 KB/秒 |
| 1 | ORIGEN | `resouce/origen_nes_256x240` | 2値 | 30fps | 6.0 KB/秒 |
| 2 | TK REMIX | `resouce/Tetsuy_Komuro_Remix.webm_nes_256x240` | 4値グレー | 12fps（元は 24fps） | 4.5 KB/秒 |
| 3 | 2026AI | `resouce/2026AI_nes_256x240` | カラー、4×4 ドットのモザイク | 10fps（元は 60fps） | 5 KB/秒 |
| メニュー | — | `resouce/PuniNeko_nes_240h`（右に寄せ、左を文字用に空ける） | 2値 | 60fps | 6 KB/秒 |

音声は DPCM 11.2kHz（`audio_rate`: 9）。ORIGEN（そのぶん映像を 6.0 KB/秒に）とメニューの BGM は 24.9kHz（`audio_rate`: 14）。

スプライトは 1 行に 8 個までしか並ばないので、メニューの文字は 1 行 8 文字以内にしています
（「Tetsuy Komuro Remix」は「TK REMIX」）。文字は `nes/src/video.s` の末尾にあります。

### titles.json で変えられること
| 項目 | 内容 |
|---|---|
| `mode` | `mono`（2値）/ `gray`（4値グレー）/ `color`（場面ごとのパレット 4 組）/ `pal4`（決まった 4 色、フル解像度） |
| `colors` | `pal4` の 4 色（ファミコンの色番号、例 `["0F","30","16","1A"]`）。各点をいちばん近い色にする。1 つ目が背景色 |
| `fill_gaps` | `true` にすると連番の抜けを直前のコマで埋める（長さがずれないように） |
| `append` | 動画の後ろに足す画面のリスト。1 件ごとに `nes_frames`（1/60 秒単位）か `seconds`、`base`（`last` = 最後のコマ / `black` = 黒 / 省略 = 1 つ前の画面）、`texts`（`text` `y` `size` `font` `align` `x` `width`）。文字はにじみなしで書く |
| `step` | 何コマおきに使うか（2 なら半分の fps）。動きの多い動画は下げると 1 コマあたりの量が増えてきれいになる |
| `kbps` | 映像の 1 秒あたりの ROM のバイト数の上限（KB）。上げるときれいになるが ROM が増える |
| `pixel` | カラーの粒の大きさ。4 = 4×4 ドットのモザイク（タイルの種類が 256 に収まるので崩れにくい）/ 1 = そのまま |
| `snap_seconds` | コマ戻し用スナップショットの間隔（秒）。短いとコマ戻しが速いが ROM が増える |
| `audio_rate` | DPCM の速さ（`$0`〜`$F`）。9 = 11.2kHz、12 = 16.9kHz。上げると音が良くなるが ROM が増える |
| `audio_enc` / `audio_swing` | 1 bit 列の決め方（`"greedy"` 既定 / `"viterbi"`）と振れ幅（既定 56）。ROM の量は変わらない |
| `audio` | 音声ファイル。省略すると「連番フォルダ名.mp4」、`false` で音なし |
| `threshold` / `levels` | 2値の境目 / 4値グレーの境目（0〜255） |
| `enabled` | `false` にするとその動画を入れない（メニューに灰色で出る） |

画像やパラメータを変えたときだけ変換し直し、それ以外は `build\video\cache\` の結果を使い回します。
**ROM は 8MB（256 バンク）まで**です。超えるとビルドが止まるので、`kbps` などを下げてください。

### ビルドのオプション
| 指定 | 内容 |
|---|---|
| `-Seconds 20` | 各動画の先頭 20 秒だけで ROM を作る（試し用） |
| `-Preview` | ROM の中身から再現した映像と音 `build\video\movies_preview_*.mp4`（音だけは `.wav`）も作る。画質・音質をパソコンで確かめられる |
| `-Test` | ビルド後に Mesen を画面なしで動かして、下の「確認したこと」を全部自動で確かめる（10 分ほど） |

### Mesen の表示について
Mesen は初期設定では上下 8 ドットずつ（昔のテレビで隠れていた部分）を表示しません。
全部を見たいときは、Mesen の「設定 → ビデオ → オーバースキャン」で上下を 0 にしてください。

## 2. 仕組み

### ファミコンで動画が難しい理由
- 画面は 8×8 ドットのタイル 960 枚でできているが、**別々の絵にできるのは 256 種類まで**
- 画面を書き換えられるのは、描画の合間（VBlank、1/60 秒ごとに約 2,270 サイクル）だけ
- ROM は BNROM で最大 8MB。4 本で約 15 分なので、音声込みで 1 秒あたり平均 8KB ほどしか使えない

### やり方
1. **書き込みデータをパソコン側で全部決めておく**
   `tools/video/make_video_rom.py` が 1/60 秒ごとに「この VBlank で PPU に書くもの」（パケット）を作り、
   ROM に並べて入れる。ファミコン側のプログラムは、それを読んで書くだけ。
2. **パターンテーブルを「タイルの置き場」として使い回す**
   画面に今いるタイルは残し、新しく要るタイルの絵だけを空いた番号に書き足す。
3. **間に合わない分は後回し**
   「直る量 ÷ 使う ROM のバイト数」が大きいものから順に選ぶ。1 回の VBlank の時間・バッファ・
   1 秒あたりの ROM の量（`kbps`、場面転換では最大 2 秒分まで先取り）のどれかが尽きたら、残りは次のフレームへ。
4. **ROM の中では位置を「前に書いた場所から何マス先か」で表す**
   変わるマスはぽつぽつ離れていることが多いので、「アドレス 2 バイト + 長さ」の代わりに「何マス先か 1 バイト」にした。
   1 マスだけなら 2 バイト（以前は 4 バイト）。これだけで ROM が 3 割ほど減った。
   ファミコン側（メインループ）が VBlank 用の形に戻してから流す
5. **明暗の反転はパレットで**
   白黒（グレーも）がほぼ反転する場面は、絵を全部書き直さずにパレットを逆順にするだけで済ませる
6. **カラーは場面ごとのパレット + モザイク**
   場面の切れ目を探し、場面ごとにパレット 4 組（背景の黒 + 3 色）を選ぶ（第2フェーズと同じ考え方）。
   16×16 ドットごとにどの組を使うかを選び、属性テーブルを書き換える。
   細かい絵はタイルが 256 種類に収まらず崩れるので、4×4 ドットを 1 粒にしたモザイク（64×60 粒）にした。
   1 タイルが 2×2 粒になり、ありうる絵がちょうど 256 種類なので、最初の 1 秒ほどで全部そろうと、
   あとは並び（ネームテーブル）と属性の書き換えだけで済む
7. **VBlank 中の書き込みを速く**
   メインループが次のパケットをスタック領域（$0100〜）に並べておき、NMI ではスタックポインタを
   そこに向けて `pla` / `sta $2007` で流し込む（1 バイト 8 サイクル、1 回に最大 224 バイト）。
8. **コマ戻しはスナップショットから早送り**
   パケットは「前の状態との差分」なので逆には再生できない。そこで数秒ごとに PPU の中身まるごと
   （2値: ネームテーブル + タイルの絵 2KB + 反転 = 3,009 バイト / グレー・カラー: ネームテーブル・属性 + 絵 4KB + パレット = 5,136 バイト）
   を ROM に入れておき、← を押すと「目的のコマより前で一番近いスナップショット」を書いてから、
   画面を消したまま目的のコマまでパケットを早送りする。
9. **音声は DPCM（DMC チャンネル）**。詳しくは下の「音声の仕組み」
10. **メニューの文字はスプライト**（パターンテーブル $1000 に英数字 41 文字。文字の絵はバンク 0 に置き、起動時に写す）。
   カーソルを動かしたときは、その 1 回だけパケットの代わりにスプライトを書き直す（背景が 1/60 秒止まるだけ）。
   FPS の数字は、毎秒 2 バイトだけ OAM を書き換える（そのぶん VBlank の予算を 60 サイクル残している）。

### 音声の仕組み
ファミコンの DMC チャンネルは、ROM の $C000〜$FFFF にある「1 bit ごとに音量を ±2 する」データを、
CPU を止めずに勝手に読んで鳴らします（DPCM）。今は rate $9（11.2kHz、1 秒 約 1.4KB）を使っています。

- **1 bit 列の決め方**: 既定は「目標より低ければ上げる」を 1 つずつ（振れ幅 64 ± 56）。
  titles.json の `"audio_enc": "viterbi"` で、差の 2 乗和が最小になる列をビタビ法で探す方法も選べる（`"audio_swing"` で振れ幅）。
  ただし耳で聞くと、ビタビ・振れ幅 28 はキャリアの音が目立ったので、既定にはしていない
- **セグメント**: 音声を 497 バイト（11.2kHz で約 0.36 秒）ずつに切る。DMC は「ループ再生」にしておき、
  今鳴っているセグメントの **次の** 場所を $4012/$4013 に書いておくと、終わったところで自動的に続きを鳴らす。
  割り込み（IRQ）を使わないので、VBlank 中の書き込みと取り合いにならない
- **バンクとの関係**: DMC が読む $C000〜は、映像と同じバンク切り替えの影響を受ける。そこで各バンクの後ろの方を
  N 個の置き場（512 バイト）にし、セグメント j は必ず「j mod N」番目に置く。
  そのバンクを読んでいる間に鳴りうるセグメントを全部入れておくので、途中でバンクが切り替わっても、
  同じ場所に同じ音が入っていて途切れない。N は動画ごとに、バンクの数がいちばん少なくなるように選ぶ（10〜14 個）
- **時計**: プレイヤーは「次に作るパケットの時刻」を CPU サイクル単位で数えている（1 フレーム = 29,780.5 サイクル）。
  セグメントの境目を過ぎて 4 フレーム経ったら、次の次のセグメントの場所を書く
- **一時停止・コマ戻しから再開**: その時刻のセグメントを 64 バイト単位の区切りから鳴らす。
  置き場の余り 15 バイトに「64 バイトごとの開始時の音量」を入れてあり、再開時にそれを $4011 に書いて音量の段差を防ぐ。
  コマ戻し用のスナップショットにも、その時点の時計を入れてある
- **パッドの読み取り**: DMC が ROM を読むタイミングと重なると、まれにボタンが 1 つずれて読めるので、2 回同じ値になるまで読む

### ROM の形（BNROM）
| 項目 | 内容 |
|---|---|
| マッパー | 34（BNROM、NES 2.0 submapper 2）。32KB 単位で切り替え、最大 256 バンク = 8MB |
| 1 バンク（32KB） | $8000〜: 映像のパケット / 後ろの方: 音声 N セグメント / $F000-$FFFF: プレイヤー 4KB（全バンクに同じものが入る） |
| バンク 0 | 目録（$8010〜、1 本 48 バイト）、スプライト文字（$8100〜）、スナップショット表（$8400〜） |
| CHR | CHR-RAM 8KB（$0000 = 動画、$1000 = スプライト文字） |

目録 1 本分: +0 入っているか / +1 最初のバンク / +2 スナップショットの数 / +3,+4 表の場所 / +5 音声あり /
+6 絵の形（0 = 白黒 8 バイト、1 = 4 段階 16 バイト）/ +7 音声スロット数 / +8 スロット 0 の $4012 の値 /
+9 開始音量の場所 / +10 $4010 の値 / +11〜13 セグメントの長さ / +14〜16 64 バイトの長さ / +17〜32 最初のパレット。
スナップショット表 1 件 16 バイト: 中身のバンク・場所、続きのパケットのバンク・場所、そこまでに終わったコマ数、音声の時計（3 バイト + スロット）。

### パケットの形式（ROM の中）
```
パケット = 絵の枚数 k（bit7 = 4 段階の絵で 16 バイト）
           { タイル番号, 絵 8 / 16 バイト } × k
           ネームテーブル・属性（$2000 のマス 0 から、前に書き終えた場所からの距離で表す）
             $00-$7F s, v      : s マス先の 1 マスに v
             $80-$BF s, v...   : s マス先から (下位 6bit + 2) マスに v...
             $C0 s             : s マス進むだけ
             $C1 a b / $C2 x16 : パレット $3F00 から 2 / 16 バイト
           終端 $F0 | フラグ
             bit0-1: 0 = 次のパケット / 1 = 次のバンクの $8000 から / 2 = 動画の終わり
             bit3  : このパケットで 1 コマ分が終わる（コマ送り・コマ戻し・FPS で使う）
```

## 3. 結果（2026-11-23、4 本 + 音声）

| 動画 | 長さ | 映像 | コマ戻し用 | 音声 | 元画像（減色後）と違う点 |
|---|---|---|---|---|---|
| OPENING | 8.6 秒 / 30fps（ロゴ 4.7 秒 + 停止・著作権表示・免責文） | 36KB | 15KB | なし | 平均 0.6%（かけらが速く回る所は、消し残りの点が少し出る） |
| ORIGEN | 219 秒 / 30fps | 1.45MB（6.5KB/秒） | 165KB | 310KB | 平均 1.1%（大きな場面転換の直後は数コマ崩れる） |
| TK REMIX | 305 秒 / 12fps | 1.38MB（4.4KB/秒） | 262KB | 429KB | 平均 9.2% |
| 2026AI | 317 秒 / 10fps | 1.62MB（5.0KB/秒） | 272KB | 447KB | 平均 21%（モザイクの粒で数えて） |
| メニュー背景 | 17 秒 / 60fps | 108KB（6.1KB/秒） | 18KB | 28KB | 平均 1.1% |

- ROM は 8MB（256 バンク。上限いっぱい）。表は ORIGEN を 24.9kHz にする前の数字
  （ORIGEN は 24.9kHz にして 77 バンク、音声 688KB、映像 6.0KB/秒、違う点 平均 1.3%）
  （2026-11-23 にオープニングを PuniNeko から Bad Player のロゴに差し替えて 247 → 242 バンク。
  同日 音声を 14.0kHz にして試したが、キャリアの音が増えたので元に戻した）
- VBlank の書き込みは Mesen で測って、VBlank 開始から最大 2,114 サイクル目に終わる（VBlank は約 2,273 サイクル）
- 音ズレ（音 − 映像）は −34〜+83ms の範囲（10fps の動画では「今のコマ」の時刻の刻みが 100ms なので、そのぶん大きく見える）。音飛びなし

### 画質について
- **TK REMIX**: ほぼ白黒の影絵なので見やすいが、細かい模様（星など）や大きな場面転換では崩れが目立つ。
  `kbps` を上げるか、`step` を 1（24fps）にすると変わる（そのぶん ROM が増える）
- **2026AI**: 細かいイラストで、しかも常にゆっくり動き続けるので、8MB に収めるには 4×4 のモザイク・10fps が限界。
  人物の形と色はわかるが、細部はつぶれる
- 容量を増やすには、ほかの動画の `kbps` や `audio_rate` を下げて回す（例: ORIGEN の `kbps` を 1 下げると約 7 バンク空く）

## 4. 確認方法

| 確認 | 方法 |
|---|---|
| ROM の中身 | 書き出した ROM をパソコン側で読み直し、プレイヤーと同じ処理をした結果がエンコーダの計算と一致するか。スナップショットがその時点の中身と一致するか。どのパケットを読んでいる間も鳴るべき音声が同じバンクにあるか（毎回自動） |
| Mesen での動き | `.\build_video.ps1 -Test`。Mesen の `--testrunner`（画面なしで動かすモード）で `build\video\movies_mesen_test.lua` を動かす |

`-Test` で確かめていること（2026-11-23 すべて OK、28 項目 + 音声）:
- 起動するとメニュー、スプライトの文字が出る、背景が動く
- Origen の 600 フレームの画面が、エンコーダの計算と 1 ドット残らず一致
- 一時停止、→ のコマ送り（画面がそのコマの正しい絵になる）
- ← を 70 回: 毎回ちょうど 1 コマ戻り、画面もそのコマの正しい絵（スナップショットの境目をまたぐ）
- SELECT で FPS 表示、数字が 30（または 29）
- START でメニュー、SELECT で再生モード切り替え
- STOP: 最後で止まり、B で最初から / SEQ: Opening の次に Origen / REPEAT: Opening を繰り返す
- グレー・カラー: 400 フレームの間、PPU の中身（ネームテーブル・属性・CHR・パレット）がエンコーダの計算と完全に一致。コマ戻し 3 回
- 音声（`tools/video/check_audio.py`）: メニュー → Origen 40 秒 → 一時停止・再開 → コマ戻し 8 回 → 再開 → メニュー →
  カラー・グレー各 20 秒の間、毎フレーム「DMC が次に読む 1 バイト（そのときのバンクで CPU から見える値）」が
  本来鳴るべき音声データと一致するか、音ズレが ±100ms 以内か、音飛びがないか（6,765 フレームすべて OK）
