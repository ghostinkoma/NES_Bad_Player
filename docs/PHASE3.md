# 第3フェーズ: スライドショー ROM とマジコンでの実機確認

第2フェーズで変換した画像を ROM に埋め込み（最大 21 枚）、パッドで切り替える
「スライドショー ROM」を作る。これをマジコン（フラッシュカート）で実機に挿して、エミュレータとの差を確認する。

方針（PLAN.md のリスク対策）: **色はエミュレータと完全には合わない前提で、近似値で妥協する。**
→ 色見本ページを実機とエミュレータの両方で撮って見比べ、どのくらい違うかを記録するところまでを目標にする。

---

## 1. ROM を作る

### 1.1 入れる画像を用意する
`assets\slides\` フォルダに置く（最初のビルドで自動的に作られる）。名前順に並ぶので、
順番を決めたいときは `01_cat.npaint.json` のように番号を付ける。

| 置くもの | 扱い |
|---|---|
| `.npaint.json`（変換ツールの「お絵描きツール用に保存」、お絵描きツールの保存） | **そのまま使う（おすすめ）**。変換ツールで設定を詰めたものがそのまま入る |
| `.png` / `.jpg` などの画像 | ビルド時に第2フェーズの変換エンジンで変換する（既定: 画面を埋める・誤差拡散 0.75） |

画像が無くても、実機確認用のテストページ 8 枚（色見本 7 枚 + テスト模様 1 枚）だけで ROM を作れる。

### 1.2 ビルド

```powershell
.\build_slideshow.ps1
```

出力:
- `build\phase3_slideshow.nes` … マジコンにコピーする ROM（128KB + ヘッダ 16 バイト = 131,088 バイト）
- `build\slides\index.html` … 中身の一覧（エミュレータでの見え方）
- `build\slides\preview\` … 1 枚ずつの PNG（実機の写真と見比べる用）

別の場所の画像を直接指定することもできる:

```powershell
.\build_slideshow.ps1 build\converted D:\pics\photo.jpg
```

テストページを付けない（画像だけの ROM）:

```powershell
.\build_slideshow.ps1 --no-test
```

画像をその場で変換するときの設定（一括変換と同じ名前）:

```powershell
.\build_slideshow.ps1 --dither ordered --strength 0.6
```

`.\build_slideshow.ps1 --help` でオプション一覧。21 枚を超えた分は省かれる（省いた名前を表示する）。

### 1.3 エミュレータで確認

```powershell
.\run_luanes.ps1 -Slideshow
```

## 2. 操作

| ボタン（LuaNES のキー） | 動き |
|---|---|
| → / A（D / O） | 次の画像 |
| ← / B（A / P） | 前の画像 |
| START（Enter） | 自動再生 ON/OFF（5 秒ごとに次へ） |
| SELECT（I） | 番号・パッド表示の ON/OFF（写真を撮るときに消す） |

画面上: `今の番号/枚数` と状態（▶ = 自動再生中、⌛ = 読み込み中）
画面下: パッドの状態。左から **A B SELECT START 上 下 左 右**。□ = 離している、■（オレンジ）= 押している

## 3. マジコンで動かす

### 3.1 ROM の種類（マジコンの対応表と照らし合わせる）
| 項目 | 値 |
|---|---|
| マッパー | **2（UNROM / UxROM）** |
| PRG-ROM | 128KB（16KB × 8） |
| CHR | CHR-RAM 8KB（CHR-ROM なし） |
| ミラーリング | 垂直 |
| ファイル形式 | iNES（.nes） |

マッパー 2 は市販ソフト（ロックマン、魔界村など）でも使われている基本的な方式なので、
たいていのマジコンが対応している。動かない場合はマジコンの対応マッパー一覧を確認する。

### 3.2 手順
1. `build\phase3_slideshow.nes` をマジコンの SD カードなどにコピーする
2. 本体に挿して起動し、`phase3_slideshow.nes` を選ぶ
3. 下の「確認項目」を順に見て、`docs\phase3_report.md` に結果を書き込む

## 4. 確認項目

| # | 見ること | 方法 | 問題があったときの意味 |
|---|---|---|---|
| 1 | 起動して 1 枚目が出るか | 電源 ON | マッパー・ヘッダの非対応 |
| 2 | 画像の切り替え | → を押す。約 0.5 秒後に切り替わる | 4 枚目（バンク 1）以降だけおかしい → バンク切り替えの問題 |
| 3 | 切り替え中・切り替え時の表示崩れ | → を連打 / 自動再生で長めに見る | 画面上端の数行が乱れる・揺れる → VBlank 内に書き込みが収まっていない（6章） |
| 4 | パッド | 全ボタンを押して ■ になるか | 配線・読み取りの問題 |
| 5 | 色 | 色見本 7 枚を撮影し、`build\slides\preview\` と見比べる | 色の差（近似で妥協。気になる色はメモ） |
| 6 | にじみ | テスト模様。1 ドットの縦縞・市松・赤青の縞 | 実機（特に RF / コンポジット）は縦縞がにじむ・色が付くのが普通。どの程度か記録 |
| 7 | 表示位置 | テスト模様の外枠が欠けずに見えるか | テレビの表示範囲（オーバースキャン） |
| 8 | 自動再生 | START で ▶ が出て 5 秒ごとに進むか | — |

写真を撮るときは SELECT で表示を消し、部屋を暗くしてテレビの正面から撮ると比べやすい。

## 5. 仕組み

```
make_slides.py ─> build\slides\bank0〜6.bin（画像データ）+ slides_table.inc（スライド表）
                   │
slideshow.s ──(ca65 / ld65, unrom128.cfg)──> build\phase3_slideshow.nes
```

### ROM の中身（UNROM 128KB）
| バンク | 場所 | 中身 |
|---|---|---|
| 0〜6 | $8000-$BFFF（切り替え） | 1 バンクに画像 3 枚。CHR 3840 バイト × 3（+$0000 / +$1000 / +$2000）と、属性 64 + パレット 16 バイト × 3（+$3000 / +$3080 / +$3100） |
| 7 | $C000-$FFFF（固定） | プログラム、表示用タイル、スライド表 |

### ちらつかない切り替え（ダブルバッファ）
CHR-RAM 8KB にはパターンテーブルが 2 枚（$0000 / $1000）ある。表示していない方へ、VBlank のたびに
128 バイトずつ書き込む（30 回 = 約 0.5 秒）。書き終わったら 1 回の VBlank で属性・パレットを書き換え、
表示するパターンテーブルを切り替える。

これは第4フェーズで RP2354 から画像を流し込むときと同じ「VBlank 内に少しずつ書く」方式。
実機で崩れなく動けば、第4フェーズの転送方式の裏付けになる。

### VBlank の時間配分（1 フレーム）
| 処理 | サイクル |
|---|---|
| スプライト表の転送（OAM DMA） | 約 513 |
| 画像 128 バイトの転送 | 約 1,410 |
| スクロール・PPUCTRL 設定など | 約 150 |
| **合計（シミュレータで計測した最大値）** | **2,077**（VBlank は約 2,273） |

### バスコンフリクト対策
UNROM の基板には、バンク番号を書き込むときに ROM の中身とぶつかるものがある。
書き込む値と同じ値が入っている ROM の場所（`banktable`）に書くことで避けている。

### ファイル
| ファイル | 内容 |
|---|---|
| `nes/src/slideshow.s` | スライドショー ROM 本体 |
| `nes/src/ui_tiles.inc` | 表示用タイル（数字・□■・▶⌛）。`tools/slideshow/gen_ui_tiles.py` が生成 |
| `nes/cfg/unrom128.cfg` | ld65 リンカ設定（UNROM 128KB） |
| `tools/slideshow/make_slides.py` | 画像をまとめてバンクデータとスライド表を作る。色見本・テスト模様もここで作る |
| `build_slideshow.ps1` | まとめ → アセンブル → リンク |

## 6. うまくいかないとき

| 症状 | 対処 |
|---|---|
| 画面上端が乱れる・揺れる | `nes/src/slideshow.s` の `CHUNK = 128` を `64` にしてビルドし直す（切り替えは約 1 秒に遅くなるが、VBlank に余裕ができる） |
| 4 枚目以降だけおかしい | マジコンが UNROM 128KB に対応していない可能性。対応マッパー一覧を確認 |
| 起動しない | マジコンがマッパー 2 に対応しているか確認。エミュレータ（LuaNES / Mesen2）で動くかも確認 |
| LuaNES で 4 枚目以降が崩れる | `run_luanes.ps1` から起動しているか確認（LuaNES 本体のバンク切り替え不具合をホスト側で直している。コンソールに「UNROM のバンク切り替えを修正しました」と出る） |
